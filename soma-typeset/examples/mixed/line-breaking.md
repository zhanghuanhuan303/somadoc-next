# 断行质量：行内代码与标识符

含义：这是“练习 + 舞台 + 内容 + 平台集成”的成熟产品。单点功能很容易做，难的是组合、稳定性、内容、分发和信任。中文段落按全局代价断行，行内代码与英文标识符是最容易破坏灰色均匀度的两类原子。

## 长表达式

事件位置用绝对 tick，不靠逐样本累加。每次调度用 128-bit 整数计算：`sample = round(tick * tempo_num / (tempo_den * ppq))`，再把结果写进音频线程的无锁队列。这样第 n 个事件的位置只取决于 tick 本身，重放、跳转和变速都不会因为累加误差而漂移。

## 标识符

基于 `metronome-rs` 的代码与架构；`tactus-time` 负责时钟与节拍网格，`tactus-core` 负责调度状态。后者只作为差距检查清单和反例参考。实现从公开标准、公开产品资料和独立用户研究出发，执行 clean-room 流程，不复制任何既有实现的内部结构。

## 长标识符与 URL

长 URL 可以在路径分隔符后换行：`https://example.com/docs/guide/line-breaking-and-hyphenation`，行尾不会再因为一个不可拆的原子而拉开大洞。没有空格的代码串在大小写、下划线、点号处断开；如果连这些都没有，例如 `z7Kp2Qm9Xr4Tv8Bn1Lc6Wd3Fh5Jg0Sa` 这样的令牌，则按字符给出代价很高的断点，只在整行放不下时才会用到。驼峰标识符 `someVeryLongIdentifierName` 与下划线标识符 `some_long_identifier_name` 都按这些接缝处理。

## 短行与短末行

短行项作用于每一条行：末行过短会收费，段中被迫出现的孤字行也收费（ADR-0112）。当一个段落只差几个字就能收尾时，多排两三个字比留下一个孤零零的词更像一本书。这一段的作用就是让最后一行落在版心的右端附近，方便检查短行的取舍是否符合预期。
