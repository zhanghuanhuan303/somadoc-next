# 标点 trim 的标定（D04）

`crates/soma-rules` 把行边标点的可压缩量做成一类常量（`OPEN_TRIM_LEFT` 等）。
它们的语义是「这一侧最多能让多少」，不是「这一侧空了多少」。这份报告把两者分开，
并记录一次真实标定尝试的结果。

复现：

```sh
cargo run -p soma-metrics --example punct -- examples/book/out/metrics-pdf.smt
```

（表由 `scripts/book.sh` 从 MiSans + IBM Plex 生成；换一份 `.smt` 就是换一组脸。）

## 1. 实测空档

单位是 1/4096 em，取各标点类的中位数；「全角」按 advance ≥ 0.9 em 判定。

| 量 | 样本数 | 中位数 | 折合 em |
| --- | --- | --- | --- |
| 开标点左侧空档 `open.left` | 6 | 2570 | **0.627** |
| 闭标点右侧空档 `close.right` | 6 | 2570 | **0.627** |
| 中标点左侧空档 `middle.left` | 8 | 755 | **0.184** |
| 中标点右侧空档 `middle.right` | 8 | 2875 | **0.702** |
| 半角标点左侧空档 `halfwidth.left` | 33 | 161 | **0.039** |
| 半角标点右侧空档 `halfwidth.right` | 33 | 273 | **0.067** |

注意中标点两侧的不对称：`，` `。` 的字形贴在字身左侧，右边留出大半 em。

## 2. 用实测值替换常量

把六个常量改成上表的近似二分值（0.625 / 0.625 / 0.1875 / 0.6875 / 0.0625，`PAIR_TRIM` 归零），
在 `corpus/zh` + `publish-v1` 上跑评分卡：

| 指标 | 出厂常量（1/2, 1/2, 1/2, 1/2, 1/8, 1/4） | 实测常量 |
| --- | --- | --- |
| 行数 | 1213 | 1213 |
| 过压行 `over_compress` | 0 | 0 |
| emergency 行 | 3 | 3 |
| fitness 跳变 | **3** | **5**（`notice` 0 → 2） |
| 行内比例抖动 p95 | **368** | **428** |
| 页数 | 48 | 48 |

页数与断行数不变，但**断行质量的两个指标都变差**：`notice` 出现两处可避免的 fitness
跳变，抖动上升 16%。ADR-0042 已经确认 3 是 `classics` 里两行被迫松排的地板值，所以
5 是真实的退化，不是噪声。

## 3. 结论：常量是预算，不是空档

`compress_left/right` 只在线需要救急时被消耗；真正的字形位移由 ADR-0037 的墨迹上限
逐字夹住（有轮廓数据时用真实侧空，没有才回退到类别常量）。所以：

- 常量给大一点不会让标点压进字形——墨迹那道闸门保证这一点；
- 常量给到实测空档会让断行算法**失去救急余地**，于是它只能选更差的断点。

因此出厂值保持 1/2 / 1/2 / 1/2 / 1/2 / 1/8 / 1/4，实测值只作为「真实空档」的参考记在这里。
D04 由此关闭：比例值不再「未标定」，而是**标定过，并带着证据维持原值**。

## 4. 还没做的

- 真正的「叠标点挤压」（clreq §6.3.2.2）是行内的成对压缩，不是行边预算；本模型没有
  行内 trim，`PAIR_TRIM` 只是个近似。
- 只测了一张表（MiSans + IBM Plex）。再加宋体/楷体表时重跑上面的命令即可，测量本身
  是脚本，不需要人工。
