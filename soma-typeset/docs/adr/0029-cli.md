# ADR-0029: `soma` command line

- Status: Accepted
- Date: 2026-11-20
- Related: ADR-0004 (syntax frontends), ADR-0024/0025 (HTML/LaTeX frontends)
- Adds: `crates/soma-cli` (binary `soma`, `publish = false`)

## Context

Every layer exists, but using them requires writing Rust. The PRD's automation
story — "template in, content in, rendered document out" — needs one command.
The CLI is also the seam that a blind-test evaluator, a CI job, or a future
service wrapper can call.

## Decision

### One binary, two commands

```text
soma render --input <file> [--template <file>] [--engine <file>]
            [--format html|svg|json] [--out <file>] [--stats]
soma check  --input <file> [--template <file>] [--engine <file>]
```

- `render` writes HTML (default), SVG, or the canonical page JSON.
- `check` lays out and prints document facts (pages, overflow, non-normal
  blocks, canonical hash) without writing output.

### The frontend comes from the extension

`.md`/`.markdown` → `soma-md`, `.html`/`.htm` → `soma-html`, `.tex`/`.latex` →
`soma-latex`. Anything else is an error. The CLI never sniffs content: a wrong
guess would silently degrade a document.

### Defaults keep the tool usable before a designer exists

- No `--template`: a built-in A4 template (20 mm margins, 10.5 pt, 1.6 line
  height, justified, 2 em first indent, headings with `keep-with-next`,
  8 pt footnotes).
- No `--engine`: `publish-v1` through `BreakConfig::default()`.

Both defaults are visible in `soma-cli/src/main.rs`; nothing else is hidden.

### I/O is the only thing the CLI owns

Parsing, styling, layout, and rendering are library calls. The CLI never
touches `LayoutResult` fields beyond passing them to a renderer, so the gates
and the CLI necessarily produce the same bytes. `--format json` is the
canonical result with a trailing newline, suitable for golden diffs.

`--out -` and no `--out` both write to stdout; a path writes a file and keeps
stdout empty (scripts can rely on it).

### Errors

One line on stderr with the path or argument, exit code `1`. No partial output:
the render string is built in memory and only then written.

## Consequences

- The pipeline is reachable from a shell, a CI job, or an agent without new
  code.
- `gate-a.sh` gains `soma-cli` in the dependency whitelist: it may depend on
  the frontends, the layout, both renderers, the metrics table, and the engine,
  and on nothing else.
- The binary is `publish = false`: it is a tool, not a library API.
- New debt D74: no batch directory mode, no `--stdin`, no watch mode, no
  template-less document metadata overrides.

## Alternatives rejected

- **A library-only API.** Already exists; it is what the CLI calls. It does not
  solve the "one command" need.
- **Content sniffing.** Silent misparse is worse than a clear error.
- **Embedding the default template in `soma-template`.** The default is a tool
  convenience; the template layer must not ship a hidden document design.
