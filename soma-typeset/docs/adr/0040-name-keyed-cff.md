# ADR-0040: name-keyed CFF, drawn out of its `seac` composites

- Status: Accepted
- Date: 2026-11-20
- Related: ADR-0039 (CID-keyed CFF), ADR-0034 (PDF backend),
  ADR-0006 (determinism), `docs/fonts.md`
- Touches: `soma-render-pdf` only. No schema changes.

## Context

ADR-0039 embedded CID-keyed CFF and refused name-keyed faces, because making
one embeddable means replacing its charset with an identity one, and Type 2
`endchar` with four operands (`seac`) finds its two components through glyph
*names* in exactly that charset. The refusal named the missing piece: deciding
whether a glyph is a `seac` composite cannot be done by scanning for `14`,
because `callsubr` does not clear the operand stack — a subroutine may leave
the four operands a later `hstemhm` or `endchar` consumes (this is how Noto's
glyph 18817 was mis-read).

Most Latin OTFs are name-keyed. Refusing them means a PDF can only use a
TrueType Latin face, which is a real limit for a typesetting engine, not a
clean-room nicety.

## Decision

### 1. A name-keyed face is promoted to CID-keyed

The Top DICT keeps its entries except `Private` and `Encoding`; the subsetter
adds:

* `ROS` = `Adobe-Identity-0`, appending `Adobe` and `Identity` to the String
  INDEX (the SIDs are then `391 + count`);
* one Font DICT holding the original `Private` operand, with its offset
  re-based into the copied region;
* `FDSelect` format 3 with a single range;
* `CIDCount` = the glyph count.

The charset becomes identity like ADR-0039, and every glyph keeps its id.

### 2. `seac` is drawn out, not referenced

A Type 2 interpreter re-emits the glyph as a flat outline:

* operands are written out as numbers, subroutines are inlined (with the
  bias `107 / 1131 / 32768`), `return` ends the inlined body;
* hints and `hintmask` are dropped, and the mask bytes are skipped while
  walking so the stream stays aligned;
* `hsbw` moves the pen to the sidebearing, as it does in a Type 1 conversion;
* the pen position is tracked through every path operator, including
  `hvcurveto`/`vhcurveto` and the four flex operators, so the accent can be
  placed exactly.

The four `endchar` operands are `adx ady bchar achar`. The two codes are
StandardEncoding codes, so each becomes a glyph id through
`code → standard-string SID → the charset`. That table —
`src/standard_encoding.rs` — is generated by `tools/make-standard-encoding.py`
from Ghostscript's `gs_std_e.ps` and the CFF standard strings of Appendix A;
it is data from the specifications, not from any implementation.

The result is `base`, then `rmoveto(adx − pen)`, then `accent`, then
`endchar`. Dropping hints costs hinting on composed glyphs only; the geometry
is unchanged.

### 3. Anything the interpreter does not understand is an error

An unknown operator, a subroutine index outside the INDEX, a `seac` inside a
component, or a code that StandardEncoding does not name stops the render with
a message naming the glyph. A guess here draws a wrong accent that nobody
notices; an error is visible and fixable.

### 4. Glyphs that are not composites are copied byte for byte

The interpreter runs only to *find* `seac`; a glyph that ends in a plain
`endchar` keeps its original program, its hints and its subroutine calls.
CID-keyed faces never run the interpreter at all.

## Consequences

- A name-keyed CFF face (most Latin OTFs) now embeds: `/CIDFontType0` with a
  promoted program, or plain `/CIDFontType0C` when the face is already
  CID-keyed. D85 closes.
- Determinism is unchanged: the interpreter is integer-only, its subroutine
  recursion is bounded at ten levels, and every `Vec` is built in glyph order.
- The interpreter is dead weight for a Chinese-first document: ~450 lines and
  a 512-byte table that nothing on the CID-keyed path reads.
- `seac` expansion is approximate where the source used hint replacement; the
  outlines are the same, the stem hints are gone. Recorded in ADR text rather
  than debt, because it only affects rendering hints, not metrics or breaks.
