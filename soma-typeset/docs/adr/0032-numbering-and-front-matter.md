# ADR-0032: Heading levels, automatic numbers, front matter, and TOC lists

- Status: Accepted
- Date: 2026-11-20
- Related: ADR-0006 (determinism), ADR-0028 (TOC and section-start masters),
  ADR-0031 (cover and alignment), `docs/first-release.md`, `docs/debt.md`
- Touches: `soma-template` (`Selector.level`, `numbering:`, `page.front-matter`,
  `toc.leaders/figures/tables`), `soma-layout` (generated numbers, printed
  labels, leader rows, figure/table lists), `soma-latex` (`figure`/`table`
  environments, `\includegraphics`)

## Context

The first release closed D75–D77 and D73 as a single design problem: a real book
needs chapter and section numbers, front matter that is numbered differently from
the body, a contents page that shows where things are, and lists of figures and
tables. Each of those looks like a small feature, but three of them decide where
a *generated* string enters the pipeline, and the fourth decides what a page
number even means.

Constraints that shaped the decision:

- DocIR is the semantic layer. Chapter numbers are presentation: the same source
  rendered with a different template must be able to drop or restyle them
  without changing `soma.doc/1`.
- Every generated string is part of `soma.pages` and therefore of the canonical
  hash. Numbers must be deterministic and derived only from template + document.
- The layout pass already iterates to a fixed point for the TOC. New generated
  content must converge in the same loop, not add another one.
- The LaTeX frontend had no way to attach a caption to a table and no images, so
  the example could not demonstrate figure and table numbering end to end.

## Decision

### Selectors can see the heading level

`Selector` gains `level: Option<u8>`, parsed from `level: 1..=9` and matched
against `Block::Heading`/`Block::Section` levels (`None` for every other
element). A selector may be level-only. Specificity counts the level between
classes and `within`:

```text
element 1 · role 1 · classes n · within 1 · level 1
```

Rejecting `level: 0`, non-numbers, and values above 9 keeps the cascade table
small and catches typos. The level participates in `soma.template/8` and
`soma.styles/6`, so a stylesheet that uses it has a different hash than one that
does not — even when the resolved values happen to match.

### Numbers are generated by layout, never stored in DocIR

Template:

```yaml
numbering:
  headings: none | chinese-chapter | arabic-dotted
  depth: 1..3
  figures: "图 {n}"      # optional; must contain {n}
  tables: "表 {n}"
```

Rules:

- `depth` limits both which levels are numbered and how many counters a dotted
  number prints. A deeper heading stays plain.
- `chinese-chapter`: level 1 `第一章`, level 2 `第一节`, level 3 `一、`.
  Chinese numerals cover `1..=99`; larger counts fall back to digits.
- `arabic-dotted`: `1`, `1.2`, `1.2.3` from the counters, including zero
  parents (`0.1` when a document starts at level 2). Counters are not invented.
- Incrementing a level resets every deeper counter.
- Figure and table counters are independent and document-wide. The pattern's
  `{n}` is replaced textually; a captionless float consumes no number.
- A generated number is prepended as a synthetic text run followed by a space
  boundary. The separator's width comes from `Metrics::space_width`, so the gap
  is measurable and participates in justification like any other space. It is
  not a hard-coded width and it is not part of the number string.
- The TOC stores `Heading.text` *after* numbering, so contents entries and the
  body agree without a second numbering pass.

The LaTeX frontend gains `figure`/`figure*` (with `\includegraphics[opts]{path}`
and `\caption`) and `table`/`table*` (caption attached to the first `Table`
block in the environment). `\caption` inside those environments is removed from
the body before block parsing, so it never leaks into a paragraph. The off-by-one
in `\midrule` (seven bytes instead of eight) is fixed: the stray `e` was visible
in every table's first body cell.

### Front matter is a run of generated pages

Template: `page.front-matter: continuous | roman | hidden`.

Front matter is the leading run of pages whose vertical items all belong to the
generated head of the flow (cover and contents). The count is computed from the
pagination result, not guessed from item types:

```text
front = longest prefix of pages whose items are all < front_matter_items
```

Printed labels:

| Mode | Front pages | Body pages |
|---|---|---|
| `continuous` | `1..` | continues |
| `roman` | `i, ii, iii…` | restarts at `1` |
| `hidden` | empty | restarts at `1` |

`Page.printed` carries the label; `Page.number` still counts every physical
page. A folio block is emitted only when the label is non-empty, so `hidden` and
masters with `footer: 0` both produce no folio without special cases.
`{pages}` in the folio template is the **body** page count for `roman` and
`hidden`, and the physical count for `continuous`.

The TOC resolves each entry's page through `printed`, so a chapter on physical
page 3 prints `1` in a roman-mode book.

### Contents can carry leaders and float lists

Template:

```yaml
toc:
  depth: 2
  title: 目录
  leaders: true            # default
  figures: 图目录          # omit = no list; "" = untitled list
  tables: 表目录
```

Each row is one flow item with three boxes: title (indented by level), optional
leader dots, page number. Leaders are a generated run of `·` measured with the
TOC style's own advance; the run stops at the number box, so a wider number
column never overlaps it. A row is only decorated when its title fits on one
line; a wrapped row gets no leaders rather than a leader run that crosses lines.

Lists of figures and tables reuse the caption text (number included) and the
page label of the caption's flow item. A list is skipped when the template asks
for no title and the document has no captions. Lists appear after the chapter
entries, separated by their own title style.

### Schema

- `soma.template/8`: selector `level`, `numbering`, `page.front-matter`,
  `toc.leaders/figures/tables`.
- `soma.styles/6`: resolved levels and the new page/TOC fields.
- `soma.pages/8`: `Page.printed`, `toc.figures`, `toc.tables`.

## Consequences

- A book template can declare numbering and front matter; the source stays
  semantic. The example book now renders 10 pages with roman front matter,
  `图 1`/`表 1`, and a contents page listing chapters, sections, and floats.
- Generated numbers are part of the canonical result; changing `numbering`
  changes the hash, as it must.
- The TOC fixed-point loop is unchanged: captions are collected in the same
  pass as headings, and lists are only stable when the caption pages are.
- Table captions render even when no number pattern is configured (previously
  they were dropped), because dropping a caption is not a numbering decision.
- New debt: D78 (no dedicated `caption` style), D79 (contents rows are single
  object runs, so a title wider than the title box overflows instead of
  wrapping).

## Alternatives rejected

- **Store numbers in DocIR.** Numbers are presentation; storing them would make
  `soma.doc/1` depend on the template, break source round-tripping, and force
  every frontend to implement counters.
- **Number in each frontend.** Three frontends would drift; the template is the
  only layer that knows whether a book uses Chinese or dotted numbers.
- **Generate numbers in the renderer.** The TOC and page labels need the numbers
  during layout; a renderer running after pagination cannot change the page
  count or the hash.
- **Use a full-width space as the number separator.** It is collapsed to the
  same space glue with no measurable difference, and it hides a layout decision
  inside a string.
- **Count front matter by "pages before the first body item".** A page that
  holds the tail of the contents and the start of chapter one is a body page;
  the prefix rule is the only one that stays correct when contents and body
  share a page.
- **Put leaders inside the title string.** The title box is a paragraph; dots
  inside it would justify, wrap, and move the page number. A separate box keeps
  the geometry explicit.
- **Roman numbering with a crate.** The mapping is 13 subtractive pairs; a
  dependency in a `no_std` core is not justified.
