# ADR-0060: ruby annotations

- Status: Accepted
- Date: 2026-11-21
- Closes: D37
- Related: ADR-0007 (frozen kernel), ADR-0038 (fallback faces),
  `docs/debt.md` D37
- Touches: `soma-core` (`AtomKind`), `soma-rules` (`SpanKind`),
  `soma-layout` (`RubySpan`, line ascent), `soma-latex` (`\ruby`), `soma-md`
  (`[[ruby:…]]`), all three renderers, canonical page JSON

## Context

DocIR has carried `Inline::Ruby { base, annotation }` since A1, and every
frontend could produce it, but layout treated the node as its base text: the
annotation was dropped. Japanese and Chinese children's books, and any text
with 注音, render incorrectly without it.

Ruby is not a second text stream on the same baseline. The annotation sits
**above** the base, and the line has to reserve room for it or it collides with
the previous line's descenders.

## Decision

### 1. The base is one atom

`soma-rules::SpanKind::Ruby` pushes the whole base as a single `AtomKind::Ruby`
atom. Line breaking therefore measures the base only, and the annotation cannot
be separated from what it annotates. A multi-character base does not break
internally; this is the conservative choice and will be revisited if ruby over
longer phrases becomes a requirement.

### 2. The layout resolves geometry, renderers only draw

```rust
pub struct RubySpan {
    pub atom: u32,      // base atom
    pub text: String,   // reading
    pub shift: Width,   // from the base baseline up to the annotation baseline
    pub size: Width,    // half the base em
}
```

`shift = ascent(base style) + em/16`, `size = em/2`. A line containing ruby
raises its own `ascent` to `shift + size` and adds the same delta to `height`;
nothing else in the line changes. Renderers never need font metrics: the PDF
centres the annotation over the base advance, SVG uses `text-anchor="middle"`,
HTML uses `<ruby><rt>`.

### 3. Canonical form

`PlacedBlock.ruby` is written as `"ruby":[{"atom":…,"text":…,"shift":…,"size":…}]`
**only when non-empty**. A document without ruby keeps the canonical bytes it
had before this ADR, so `soma.pages/10` is unchanged.

## Consequences

- No ruby in the source means no behavioural change and no byte change.
- The line grows only when it carries ruby; other lines on the same page keep
  their positions relative to that block.
- Ruby size and gap are constants, not template properties. Making them
  configurable would add a face to the template schema for one feature; if a
  real book needs a different ratio, it gets its own ADR.
- `AtomKind` gained a variant. The breaker already treats any non-object kind
  through the font path, so the frozen cost model is untouched.
