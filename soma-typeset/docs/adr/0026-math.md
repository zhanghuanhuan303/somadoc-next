# ADR-0026: Display math (`soma-math`)

- Status: Accepted
- Date: 2026-11-20
- Related: ADR-0009 (semantics/presentation), ADR-0010 (borrow-first layer
  boundaries), ADR-0025 (LaTeX frontend produces math source), `docs/debt.md`
  D52/D54
- Adds: `crates/soma-math`; `PlacedBlock.math`; page schema `soma.pages/5`

## Context

`MathBlock`/`MathInline` have been in DocIR since A1, and the LaTeX frontend
keeps their source verbatim. Layout placed every display formula as a text
placeholder: the raw TeX source was measured as ordinary text. That is
unreadable in output, and it makes the corpus fixture claim a math page it does
not typeset.

The pipeline needs formulas as **boxes**: a width, an ascent/depth split, and a
flat list of positioned glyphs plus rules. It must stay integer-only and
`no_std`, and it must not pull a TeX engine, a math font, or a layout algorithm
into `soma-core`.

Inline math (`MathInline`) is still placeholder text; it is a separate problem
because it participates in line breaking.

## Decision

### Box model, not a TeX engine

`soma-math` parses a small TeX subset and lays it out into:

- `MathItem { text, x, y, size }` — one short symbol run, `y` measured from the
  formula baseline (positive = below);
- `MathRule { x, y, width, thickness }` — fraction bars and radical bars;
- `MathLayout { width, height, depth, items, rules }`.

Everything is `i32` in 1/4096 em, like the rest of the engine. There is no
float, no font handle, and no unsafe code. `soma-math` depends only on
`soma-core` for `Width`.

### Metric seam

`MathMetrics` asks for `advance(text, size)`, `ascent(size)` and
`descent(size)`. `soma-layout::math::MathAdapter` implements it over the
existing `soma_core::Metrics` for one `StyleId`, rescaling from the style's font
size to the requested size with the same integer truncation used everywhere
else. So a formula in a 14 pt heading measures at 14 pt without a second font
table.

### Supported subset

- symbols, `{}` groups, `^`/`_` (stacked onto a big operator, otherwise to the
  right), `\frac`, `\sqrt`/`\sqrt[n]`, `\text`, `\,` `\;` `\!` `\quad`
  `\qquad`;
- big operators `\sum` `\prod` `\int` `\oint` `\lim` `\sup` `\inf`: limits
  stack above/below for `\sum`/`\prod`/`\lim`/`\sup`/`\inf`, stay to the right
  for integrals;
- upright names `\log` `\ln` `\exp` `\sin` `\cos` `\tan` `\max` `\min`;
- Latin and Greek letters, relations, arrows, set operators, `\cdots`/`\ldots`;
- `\left`/`\right` with `()[]{}|`, `\langle`, `\lfloor`, `\lceil` and the null
  delimiter `.`. Delimiters are set at the base size: **automatic delimiter
  sizing is not implemented** (D71).

Spacing follows the class of each symbol: `bin_gap`, `rel_gap`, `frac_gap`,
`axis_height`, `rule_thickness`, `script_scale`, `scriptscript_scale`,
`sup_shift`, `sub_shift`, `big_scale`. All of them are permille fields of
`MathStyle`, so a second style is a struct literal, not a code change.

### Placement

`soma-layout` places one `PlacedBlock` per `MathBlock`:

- `math: Some(MathBox)` carries `width`, `height` (total), `baseline`
  (distance from the block top), `items`, `rules`;
- the box is centred in the content width, `x = (content - width) / 2`;
- the block height is `height + depth`, so vertical pagination treats the
  formula as one indivisible box;
- the block has no text lines (`lines` empty, `lines_total = 0`), so line
  counts, widow/orphan logic and line-level trim never see it.

A formula that fails to parse **never fails the page**: layout keeps the old
text placeholder (`math: None`, one text line).

### Rendering

`LayoutResult` stays font-free, so `MathBox` carries the baseline instead of
asking renderers to guess it.

- SVG writes `<text>` at `y = margin_top + block.y + baseline + item.y`
  (SVG text positioning is baseline-relative, so this is exact) and `<rect>`
  for rules.
- HTML writes absolutely positioned spans; CSS has no baseline positioning, so
  the span top is approximated as `baseline - 7/8 em` of the item size. The
  HTML renderer is a preview; SVG is the geometry-faithful output.

### Schema

Page schema becomes `soma.pages/5`: every block gains
`"math": null | {width, height, baseline, items:[{text,x,y,size}], rules:[{x,y,width,thickness}]}`.
A text placeholder serializes as `"math":null`, so the placeholder path keeps
byte-stable output.

## Consequences

- A display formula is now a real box: the corpus `math-page` fixture drops
  from 7 text lines to 5 and carries six math boxes.
- `soma-layout` gains a dependency on `soma-math`; `gate-a.sh` whitelists it.
  `soma-core` is untouched, so the frozen inline kernel is unaffected.
- No template, engine, or DocIR change. Math styling uses the ordinary cascade:
  `font-size` sets the base size, `color` paints items and rules.
- New debt: D71 (no delimiter sizing, no `\begin{aligned}`, no matrices, no
  math font table, no inline math layout).

## Alternatives rejected

- **Embed Typst/TeX math layout.** Reintroduces the dependency graph the
  architecture forbids and makes the page result non-reproducible.
- **Keep formulas as text.** Free but wrong: the pages claim to typeset math
  and do not.
- **Store only a width/height for the formula.** Renderers would have nothing
  to draw, and the visual gate could not check positions.
- **Let the renderer compute baselines from a math font.** Renderers must not
  open fonts; the baseline belongs to the layout result.
