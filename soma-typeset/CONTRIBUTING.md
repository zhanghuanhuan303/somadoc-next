# Contributing

Thanks for taking a look. This repository is a deterministic typesetting
engine, not a general-purpose word processor. The most useful contributions are
small, reproducible changes with a failing test or a measured baseline behind
them.

## Ground rules

- **Clean room.** Do not read or copy line-breaking code from Typst or another
  typesetting engine. Public algorithm descriptions and published standards are
  fine; cite them in the ADR.
- **ADR first.** A change to layout behavior, a schema, a parameter, a default
  template, or a font-facing rule starts with an ADR in `docs/adr/`. Accepted
  ADRs are not rewritten; add a new one.
- **Determinism.** The core uses integer units (1/4096 em), no `f32`, canonical
  JSON, and fixed iteration order. Native and wasm builds must produce the same
  canonical bytes. Do not introduce floating point into layout.
- **Explain the baseline.** If a gate or corpus number moves, say why in the
  commit and update the relevant document.
- **No secrets or generated artifacts.** Do not commit fonts, PDFs, `dist/`,
  `target/`, credentials, or environment files. See `.gitignore` and
  `scripts/local-assets.sh`.

## Setup

Rust 1.85 or newer is required. The browser slice also needs the wasm target;
the Studio UI needs `trunk` and, for the S gates, Chromium.

```sh
rustup target add wasm32-unknown-unknown wasm32-wasip1
cargo test --workspace
```

Optional tools:

```sh
# Studio UI
cargo install trunk

# GB2312 browser fonts (needs fonttools)
python3 -m pip install fonttools
SOMA_FONT_DIR=/path/to/fonts bash scripts/local-assets.sh
```

`SOMA_FONT_DIR` must contain the five faces named in `scripts/local-assets.sh`
(Plex regular/bold, Noto Sans Mono regular/bold, New Computer Modern Math).
The script writes `dist/fonts/v2/` and `dist/welcome.md`; neither is committed.

## Checks

Run the core gates before opening a pull request:

```sh
bash scripts/gates.sh       # format, clippy, tests, wasm, demo, boundaries, gates
bash scripts/studio.sh      # S1–S11 server mode (needs chromium)
bash scripts/web.sh         # W1–W6 browser slice
cargo test --workspace      # 1,006 tests (1 ignored)
```

For the browser-local path, build the UI and run the public-equivalent
self-test:

```sh
(cd crates/soma-studio-ui && trunk build --release)
SOMA_FONT_DIR=/path/to/fonts bash scripts/local-assets.sh
# serve crates/soma-studio-ui/dist and open ?local=1&selftest=1
```

S12 checks a local PDF in wasm (`%PDF-` header, size, elapsed time). S2/S11 are
server file-tree tests and are skipped in local mode by design.

## Change workflow

1. Open an issue for a behavior change or a new capability; for a tiny typo or
   test-only fix, a PR is enough.
2. Write the ADR (if needed), then the test/golden, then the implementation.
3. Run the narrow test, then `scripts/gates.sh`, then the Studio/web gates when
   the change touches them.
4. Update `docs/debt.md`, the atlas (`docs/soma-atlas.html`), or the schema
   documents if the change visible to users moves a number or a boundary.
5. Use a focused commit message in the imperative. The repository logs the
   context in ADRs, not in long commit bodies alone.

## Code style

- `cargo fmt --all` and `cargo clippy --workspace --all-targets -- -D warnings`
  must pass.
- Keep the core `no_std + alloc` where it is today; do not add a dependency to
  `soma-core` without discussing it first.
- Prefer integer arithmetic and explicit ordering over clever iterators in the
  layout path.
- Comments explain intent, constraints, and tradeoffs; do not restate code.

## Fonts and assets

- The repository commits **one** font binary: the New Computer Modern Math face
  used by the CLI. Its GUST license text is next to it.
- CJK metrics are numbers only (`.smt`), generated by `tools/metrics-gen`.
- The browser Studio loads GB2312 subsets at runtime; they are generated into
  `dist/fonts/v2/` and never committed.
- Do not add a font, a PDF, a screenshot, or a generated HTML page without a
  provenance note and a license compatible with redistribution.
